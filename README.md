# CoStep

[![IMAGE ALT TEXT HERE](https://jphacks.com/wp-content/uploads/2026/07/IMG_5316.png)](https://www.youtube.com/watch?v=piaNsc6ilBI)

## 製品概要

**同じ目標へ、近い歩幅の仲間と。**

CoStepは、学習分野・習熟度・目標が近い仲間とつながり、自分に合った学習方法の発見と、継続的な学習を支援するIT学習者向けSNSです。

### 背景(製品開発のきっかけ、課題等）

生成AIやオンライン教材の普及により、一人でもIT学習を進めやすくなりました。一方で、自分に合った学習方法を見つけたり、同じ目標を持つ仲間と気軽につながったりすることには、依然として難しさがあります。

たとえば、インターネットで公開されている「応用情報技術者試験に3か月で合格するロードマップ」が、すべての人に適しているとは限りません。必要な学習時間や勉強法は、これまでの経験や知識、生活環境によって異なります。

また、初学者のなかには、経験豊富な人が集まる場では質問や発信をためらう人もいると考えています。

そこで私たちは、自分と近い段階で学ぶ仲間を見つけ、相談し、励まし合える場としてCoStepを開発しました。

### 製品説明（具体的な製品の説明）

利用者は、学習分野と目標をプロフィールに登録します。技術分野では習熟度、資格学習では累計学習時間を用い、同じ分野での学習経験を比較します。CoStepは、その情報をもとに学習状況が近い利用者をおすすめします。

学習内容・時間・振り返りを記録し、疑問や成果を投稿できます。コメントやDMを通じて、自分の状況に近い仲間の体験を参考にしたり、日々の進捗を共有したりすることで、学習の継続を後押しします。

### 特長

#### 1. 自分と近い学習段階の仲間が見つかる

学習分野の一致に加え、技術の習熟度や資格学習の累計時間、目標の近さをもとに、おすすめする利用者を選びます。「同じことを学んでいる」だけでなく、「今、どの段階で学んでいるか」をつながりのきっかけにします。

#### 2. 記録と交流で、学びを続けやすくする

学習分野・日付・時間・メモを記録し、カレンダーや集計から自分の学習を振り返れます。投稿・コメント・リアクション・DMにより、小さな成果の共有から個別の相談まで、交流のきっかけをつくります。

#### 3. 安心して共有するための仕組み

文章の公開範囲、フォロー承認、DMの受信設定、ブロックを用意しています。サーバーとDBでの認証・権限確認、操作回数制限、任意の二要素認証なども組み合わせています。

Git履歴と公開JavaScriptへの秘密情報混入を自動検査し、ログイン・二要素認証・復旧要求の件数増加も監視します。検知や監視取得不能時はGitHub Issueで運営へ通知します。監視には個人情報や秘密の値を記録せず、鍵の失効・交換は運営が手順に沿って実施します。すべての漏洩や、Supabaseへ直接行われる不正アクセスを検知できるものではありません。

文章の公開範囲と、プロフィール・学習時間の公開範囲は異なります。プロフィールと学習分野・日付・時間は、原則としてログイン済みの利用者に表示されます。投稿本文・現在の画面から登録する学習メモは、「ログイン済み全員」「承認済みフォロワーのみ」「自分のみ」を文章の共通公開設定として選択できます。

### 解決出来ること

* 自分の学習段階に近い人の体験から、参考にしやすい学習方法を見つけるきっかけをつくります。
* 一人で抱えていた疑問や悩みを、仲間に相談しやすくします。
* 学習記録と日々の交流を通じて、意欲の維持と継続を支援します。
* 初学者が、同じ段階で学ぶ仲間と気軽に発信できる場を目指します。

### 今後の展望

まずは招待制テストを通じて、学習状況が近い仲間を見つけやすいか、交流が学習の継続につながるかを検証し、おすすめや交流機能を改善します。

将来的には、法律・簿記など他分野の学習者や、学生から社会人まで幅広い利用者への展開を検討しています。IT企業のスポンサーシップや広告による収益化も構想の一つです。

現在の招待制は運用方針であり、招待コードやメール許可リストによる登録制限は未実装です。退会・通報・管理機能、問い合わせ窓口や個人情報の取扱いなども整備し、実環境での動作確認を進めます。

### 注力したこと（こだわり等）

* **学習状況の近さをつながりに生かすこと**：学習分野・習熟度・累計学習時間・目標を組み合わせ、おすすめする利用者を選びます。DMや限定公開の文章をおすすめの材料には使用しません。
* **DB側でも情報を守ること**：画面で非表示にするだけでなく、DB関数で本人・公開範囲・フォロー承認・ブロックを確認します。DMの取得は会話の当事者、投稿の削除は投稿者本人に限定します。
* **学習の振り返りと交流を一つの場で行えること**：記録を残すだけでなく、投稿や会話を通して次の学習につなげる体験を目指しています。

## 開発技術

### 活用した技術

#### API・データ

* **Supabase Auth**：メールアドレス・パスワードによる認証、メール確認、任意の二要素認証。
* **Supabase Database / PostgreSQL**：プロフィール、学習記録、投稿、フォロー、DMなどの保存と権限制御。
* **SMTP / Nodemailer**：二要素認証の復旧メールなどの送信。登録確認・パスワード再設定のメールはSupabase Auth経由で送信します。

#### フレームワーク・ライブラリ・モジュール

* **Next.js / React / TypeScript**：画面とサーバー処理。
* **Zod**：入力値の形式・範囲の検証。
* **Sharp / react-easy-crop**：プロフィール画像の切り抜き、サイズ調整、再変換。
* **Lucide React**：画面内のアイコン。
* **Node.js Test Runner / tsx / PGlite**：単体テスト、DB権限などの検証。
* **Vercel**：Webアプリの公開・実行。
* **Git / GitHub / GitHub Actions**：変更履歴の管理、テスト・ビルド・セキュリティ検査用ワークフロー。
* **CodeQL / Dependabot / Gitleaks**：コード解析、依存関係の更新PR、Git履歴・公開ファイルの秘密情報候補検査。GitHub標準のSecret Scanning・push protection・必須チェックの強制は、管理者による設定確認が別途必要です。
* **jose / GitHub OIDC**：定期監視から集計APIを読む際の署名付き認証。
* **OpenAI Codex**：実装・修正・テストの開発支援。

#### デバイス

* PC・スマートフォンのWebブラウザでの利用を想定しています。
* ホーム画面への追加に対応するPWA構成を用意しています。学習記録やDMの表示・保存にはインターネット接続が必要です。

### 独自技術

#### ハッカソンで開発した独自機能・技術

* **学習状況に基づくおすすめ**：利用者が登録した学習分野・習熟度・累計学習時間・目標から近さを計算し、おすすめする利用者を選びます。関連実装：`supabase/migrations/202610170005_recommendations.sql`、`supabase/migrations/202610170018_experience_and_feed.sql`、`supabase/migrations/202610170020_cumulative_study_time.sql`。
* **学習記録とタイムラインの連携**：学習時間・メモ・投稿を組み合わせ、文章の公開範囲に応じて表示内容を制御します。関連実装：`supabase/migrations/202610170013_study_memo_visibility.sql`、`202610170018_experience_and_feed.sql`。
* **交流機能とDBの権限制御**：フォロー承認、DM受信設定、ブロック、操作回数制限をDB側の処理にも反映します。関連実装：`supabase/migrations/202610170002_conversations.sql`、`202610170003_follow_approval.sql`。
* **二要素認証とメール復旧の連携**：認証段階をDBでも確認し、復旧時にはパスワード再確認・登録メールへのコード送信・有効期限・試行回数制限などを組み合わせています。関連実装：`src/app/api/mfa/`、`supabase/migrations/202610180021_optional_mfa.sql`以降。

* **公開ファイルと認証処理の監視**：公開トップページから発見できるJavaScriptを約30分ごと、認証・復旧処理の直近30分の集計を約15分ごとに確認します。実行遅延や検出範囲の限界はあります。設計としきい値：[監視仕様](docs/RUNTIME_SECURITY_MONITOR.md)。
* **漏洩対応の準備**：復旧機能のみ／アプリ全体の停止設定と、既存アプリセッションの無効化設定を用意しています。停止・失効・鍵交換は自動実行せず、運営が実施します。[対応手順](docs/INCIDENT_RESPONSE.md)。

これらは既存の技術・サービスを組み合わせて実装したCoStepの機能です。安全性の確保には、本番設定の確認と継続的なテスト・運用も必要です。
