# 学習記録SNS セキュリティ要件定義書 v1.0

作成日：2026-10-17／状態：要件初稿・実装未確認

本書は利用者提供の最新要件定義と会話で合意した仕様をセキュリティ要件へ具体化する。**要求事項を記述した文書であり、実装済み・設定済み・検証済みを意味しない。全要件の初期状態は未確認。**

## 1. 目的・対象・文書の位置付け

IT学習者が、学習分野・目標・習熟度の近い仲間を発見し、記録と交流を通じて学習を続けられることを目的とする。主なターゲットは大学生・社会人だが、18歳未満も利用可能。共同開発や起業の仲間探しは副次的な用途とし、本名・所属の公開を前提にしない。

対象構成は暫定でNext.js + Vercel + Supabase + PWA。ハッカソン起点、月額0円志向、将来一般公開の可能性あり。0円は費用保証ではなく、必要な対策を外す理由にしない。

既存 security_policy_Ver2.md は基本方針として継続適用する。本書で確定した機能仕様は対応する旧暫定仕様を更新し、その他の重要事項は削除しない。原典Ver.1の保持・対応表はVer.2を参照する。新しい利用者の指示が優先され、未確定事項を黙って決定しない。

### 1.1 優先度と状態

| 優先度 | 規範・時期 |
|---|---|
| P0 MUST | 当該機能を有効化する前に必須。未達ならマージ・公開しない |
| P1 MUST | 実ユーザー・実データ受入前に必須。限定デモは疑似データ・機能無効化で範囲を制限 |
| P2 SHOULD | 原則実施。延期時は理由・代替策・担当・期限を記録 |

機能の開発順と対策の重要度は別。未完成機能はAPI・権限・配信まで無効化し、未完成と報告する。実装状態は unverified / implemented / verified / failed / not_applicable。実装済みと検証済みを区別する。

## 2. 機能範囲

必須機能：ログイン、学習分野・習熟度設定、学習記録管理、学習レベルが近いユーザー推薦、3種類のタイムライン（近いレベル・個人向けおすすめ・フォロー中）、つぶやき、タグ、フォロー、返信コメント、DM、アプリ内通知、Webプッシュ。

安全な交流に必要なブロック・通報・停止・運営管理も実ユーザー受入条件に含める。

任意機能：週次の学習記録をもとに励ましの文章を作りPDF化するAIレポート。外部LLM・PDF生成・自動スケジュールは未実装・未採用。任意機能を必須機能の完成条件へ混ぜない。

## 3. 確定した公開・操作仕様

「全員」「全ユーザー」はログイン済みユーザーを指す。登録・ログイン・メール確認・再設定の必要最小限の入口だけは未認証で利用可能だが、プロフィール・記録・投稿等は返さない。

| 情報・機能 | 確定ルール |
|---|---|
| 基本プロフィール・自己紹介 | ログイン済み全ユーザーへ公開 |
| 学習時間タブ | つぶやきと分離。学習分野・学習日・学習時間グラフを全ユーザーへ公開。画像は添付不可 |
| 学習記録の文章・つぶやき | 登録時にアカウント全体の文章公開範囲を選択。初期選択は相互フォローのみ |
| 文章の公開選択肢 | 全ユーザー／相互フォローのみ／自分のみ。投稿単位の設定にはしない |
| 過去の文章 | 最新の全体設定に従う。相互解除後は過去の相互限定文章も閲覧不可 |
| つぶやきに添付した画像 | 本文と同じ公開範囲。画像URLの直接取得にも適用 |
| 教材名・タグ | 全ユーザー公開の合意。ただし置き場所とつぶやき内タグの扱いはQ02で確認。限定本文を漏らすタグの自動公開は行わない |
| フォロー人数 | 基本プロフィールと同じ公開範囲 |
| フォロー・フォロワー一覧 | 本人のみ |
| 返信コメント | 親のつぶやきを閲覧できれば非相互でも投稿可能。ブロック・停止は除く |
| DM受信設定 | 本人が相互フォローのみ／誰でもを選択。初期値は相互フォローのみ |
| 非相互からのDM | 誰でも受信時はリクエスト。承認前は1申請につき1件のみ |
| DM申請回数 | 初回を含め同じ相手へ合計2回。削除・フォロー変更でリセット不可 |
| DM設定変更 | 既存会話も最新設定に従い新規送信を判定。過去履歴は残す |
| DM削除 | 送信者が自分のメッセージを削除。双方に「メッセージを削除しました」を表示 |
| ブロック | 双方向の新規接触を拒否。投稿・学習実績を相互に非表示。過去DMは閲覧のみ可能 |
| 利用停止 | 少なくともコメント・DM送信不可。その他の操作範囲はQ06 |
| おすすめ掲載 | 掲載拒否可能。分野・習熟度・目標を基本に使用 |
| 退会 | プロフィール・記録・投稿・画像・返信・送信DM等、本人由来のデータを削除する方針 |

公開設定変更は過去投稿にも影響するため、公開を広げる変更では影響を画面で説明・確認する。公開用情報と文章・画像はサーバー応答でも分離する。

## 4. 匿名性・未成年への配慮

匿名性は最新要件で検討中。**ニックネーム方式を推奨案として記載し、本名必須と勝手に確定しない。**

| ID | 優先度 | 要件 |
|---|---|---|
| PRIV-01 | P0 MUST | 認証用メール・内部IDと、公開表示名を分離する。公開APIへメール・認証情報・端末識別情報を返さない |
| PRIV-02 | P1 MUST | 本名・正確な住所・学校/勤務先を登録必須にしない案を採用判断する。居住地は機能未確定であり自動追加しない |
| PRIV-03 | P1 MUST | 居住地採用時は任意・粗い地域を基本とし、正確な住所/現在地を公開しない。公開項目を説明する |
| PRIV-04 | P1 MUST | 未成年利用を前提に個人情報・外部連絡先・画像の注意喚起、ブロック、通報、勧誘・嫌がらせへの対応を用意する |
| PRIV-05 | P0 MUST | 匿名表示を完全匿名・追跡不能と説明しない。運営や認証基盤が情報を扱う範囲を明示する |

### 5.4 DM・ブロック・利用停止

| ID | 優先度 | 要件 | テスト |
|---|---|---|---|
| DM-01 | P0 MUST | 本文・会話・検索・件数・Realtimeは参加者限定。送信者偽装・参加者の勝手な変更を拒否 | T16 |
| DM-02 | P0 MUST | 毎送信時に受信者の最新設定、相互関係、ブロック、停止、承認状態を検証。既存会話も例外にしない | T17 |
| DM-03 | P0 MUST | 承認は受信者のみ。承認前1件、初回込み2申請を永続・原子的に強制。同時申請/削除/フォロー変更でリセット不可 | T18 |
| DM-04 | P0 MUST | 2回目は最初が解決してから申請できる案とし、未承認中の重複を拒否。待機時間/拒否の扱いはQ03で確定 | T18 |
| DM-05 | P0 MUST | 自分の送信DMのみ削除可。双方へ削除表示を返し、本文・引用・検索・未送信キューから元本文を除去 | T19 |
| DM-06 | P0 MUST | 削除済本文をログ・通知・推薦へ出さず、バックアップ残存/削除期限を設計。スクリーンショット回収を保証しない | T19 |
| BLOCK-01 | P0 MUST | ブロック後の双方向接触・投稿/学習実績閲覧を拒否し、過去DMは閲覧のみ。解除で旧関係や申請枠を自動復元しない | T20 |
| STOP-01 | P0 MUST | 停止前JWTでもコメント/DM不可。停止・権限は本人変更不可。他操作の停止範囲は別途確定 | T21 |

DMのエンドツーエンド暗号化は未採用。HTTPS/保存先保護と混同しない。運営の通常DM本文閲覧は不可、通報として提供された証拠のみ限定的に扱う。

## 6. アプリ全体のセキュリティ

| ID | 優先度 | 要件 |
|---|---|---|
| SYS-01 | P0 MUST | 改造可能なクライアントを信用せず、認証と認可を分離。原則拒否・最小権限。画面非表示のみで制御しない |
| SYS-02 | P0 MUST | Data API公開テーブルのRLS・操作別USING/WITH CHECK・所有者固定・列権限・GRANT/REVOKE/default privilegesを管理 |
| SYS-03 | P0 MUST | Viewのsecurity_invoker等、関数のinvoker/definer・固定search_path・EXECUTE権限、RPC/Storage/Realtime全経路をレビュー |

| SYS-05 | P0 MUST | XSS安全表示・強制CSP・Cookie認証のCSRF/Origin検査・CORS制限・HTTPS・安全なセッション保存/更新/失効 |

| SYS-09 | P0 MUST | 本番/開発/preview分離、再現可能マイグレーション、依存/秘密/静的解析/権限テスト、Advisor確認 |
| SYS-10 | P0 MUST | AI生成コードを未検証案として差分レビュー。RLS無効化、無根拠な全件許可、テスト削除、警告隠し、架空結果は禁止 |
| SYS-11 | P1 MUST | 通報・運営削除・警告・停止/解除・監査、管理者MFA・専用認可。編集可能プロフィールで管理者判定しない |

| SYS-16 | P2 SHOULD | 一般利用者MFA、監視/復旧自動化、推薦悪用検知を改善。延期理由・代替策・担当・期限を記録 |

運営担当・復旧目標の詳細は利用者の希望で現在保留する。現時点の設計/疑似データ開発は進められるが、実ユーザー受入前の確認条件として残す。無料で実現できない必須対策は機能・人数・公開範囲を縮小するか公開を延期する。

GitHubへコード・設定項目名だけの.env.example・マイグレーションを提出することと、実秘密を除外することは両立する。実値は非追跡のローカル設定/ホスティング環境変数/CI Secretsへ保存する。漏えい時は削除コミットだけでなく失効・再発行する。

## 2026-10-17 午後：利用者合意による仕様更新

この追記は本文の旧仕様より優先する。
- VIS-01：文章の公開範囲選択をメール/パスワード登録画面から、登録直後のプロフィール設定へ移す。初期値は相互フォローのみ。設定保存前は投稿を拒否し、metadataから全公開を指定させない。
- FOLLOW-01：方向別に申請と受信者の承認を必要とする。承認で逆方向の関係を作らない。両方向とも承認済みの場合だけ相互となる。承認前は人数・フォロー中フィード・相互限定閲覧・相互DMの条件に含めない。既存の承認なし関係はpendingへ移し、再承認を必要とする。
- 受入：第三者/申請者による承認拒否、片方向の承認で限定投稿非表示、両方向承認後の表示、取消/拒否/ブロック後の非表示、プロフィール設定前の直接RPC投稿拒否を確認。
